# AlphaLens MVP 验收测试场景

日期：2026-08-04

使用技能：Test Scenarios

## Testing Principles

- 验收观察用户可见行为和持久化结果，不只检查组件存在；
- 使用真实形状数据，明确区分模拟 provider 与伪造产品成功状态；
- 美股/A 股、桌面/移动、AI 可用/不可用均覆盖；
- 不把盈利结果作为通过条件；
- 每个失败、未知和过期状态必须可操作且不伪造替代内容。

## AT-01 今日首页按市场会话组织真实待办

**Test Objective:** 验证“今日”根据用户市场、时区和会话状态排序真实任务。

**Starting Conditions:**

- 用户选择一个市场和时区；
- 存在一个今日候选、一个等待计划、一个未审查计划和一个待复盘成交；
- 测试时钟可固定为盘前、盘中、盘后和休市四种状态。

**User Role:** 主动交易者。

**Test Steps:**

1. 依次切换四种测试时钟并打开 `/today`；
2. 检查会话标签、市场、日期和数据新鲜度；
3. 检查首要待办排序是否随时段变化；
4. 点击候选、计划和复盘待办；
5. 返回首页确认状态来自真实记录而非静态卡片。

**Expected Outcomes:**

- 四种会话状态准确；
- 两个市场的时区和涨跌语义不混用；
- 点击进入正确业务对象；
- 空数据时显示下一步，不生成假候选；
- 过期数据显式标注。

## AT-02 CANSLIM 作为可保存筛选模板

**Test Objective:** 验证 CANSLIM 不再是唯一硬编码筛选逻辑，而是结构化模板。

**Starting Conditions:** 有可用股票池、CANSLIM 模板和至少一个额外技术/流动性条件。

**User Role:** 主动交易者。

**Test Steps:**

1. 打开“发现”并载入 CANSLIM 模板；
2. 修改一个 CANSLIM 阈值并增加流动性条件；
3. 保存为新模板；
4. 切换市场与标签过滤后返回；
5. 重新运行模板并打开一个候选解释。

**Expected Outcomes:**

- 原始默认模板未被意外覆盖；
- 新模板可重复运行；
- 市场与标签过滤非破坏性组合；
- 候选展示命中、未满足、未知条件和数据时间；
- 未知数据不被自动当作通过。

## AT-03 候选快照不会被后续扫描改写

**Test Objective:** 验证研究和计划引用的是当时的候选原因。

**Starting Conditions:** 同一标的在两次扫描中拥有不同指标或数据日期。

**User Role:** 主动交易者。

**Test Steps:**

1. 从第一次扫描把标的加入研究队列；
2. 创建研究与用户观点；
3. 运行第二次扫描；
4. 返回第一次研究；
5. 对比当前数据与候选快照。

**Expected Outcomes:**

- 第一次入选理由、规则和时间保持不变；
- 当前数据作为新状态显示，不覆盖历史；
- 用户能看到数据发生变化；
- 来源失败时历史快照仍可读取。

## AT-04 AI 研究补全思考但不替用户决定

**Test Objective:** 验证研究输出区分事实、推断、多空、未知和证伪条件，不使用批准交易语义。

**Starting Conditions:** 一个有事实数据和部分缺失数据的研究标的，AI provider 可用。

**User Role:** 主动交易者。

**Test Steps:**

1. 运行多角色研究；
2. 查看基本面、多头、空头、风险和未知；
3. 检查来源与数据日期；
4. 保存用户自己的观点、反对论点和证伪条件；
5. 从观点创建交易计划。

**Expected Outcomes:**

- AI 研究没有“批准/计划通过”行为；
- 事实与模型意见视觉和语义分离；
- 缺失数据保持未知；
- 用户观点是独立持久化对象；
- 计划引用用户观点和研究 ID，而非只复制 AI 摘要。

## AT-05 计划确定性校验在 AI 不可用时仍工作

**Test Objective:** 验证计划数学和字段冲突不依赖 LLM。

**Starting Conditions:** AI provider 不可用；用户创建一个止损方向错误或风险预算冲突的计划。

**User Role:** 主动交易者。

**Test Steps:**

1. 填写触发价、入场价、止损、仓位和最大风险；
2. 保存计划；
3. 请求快速风险审查；
4. 修复冲突并再次审查。

**Expected Outcomes:**

- 第一次保存或审查明确指出具体字段冲突；
- 不生成替代 AI 报告；
- 非 AI 冲突修复后可继续；
- UI 明确区分确定性校验和 AI 审查不可用。

## AT-06 AI 风险审查引用当前证据

**Test Objective:** 验证每条高风险提示与计划、市场证据或历史样本关联。

**Starting Conditions:** 有完整计划、当前技术/新闻上下文和一条满足最低样本的历史行为观察。

**User Role:** 主动交易者。

**Test Steps:**

1. 运行计划风险审查；
2. 展开 hard conflict、风险、行为和未知分区；
3. 打开每条高风险提示的引用；
4. 修改计划并重新运行；
5. 确认一条高风险提示并记录理由。

**Expected Outcomes:**

- 提示可追溯到具体字段、来源或样本；
- 过期数据降低置信度或变为未知；
- 计划修改产生新审查版本，不覆盖旧版本；
- 系统不输出交易批准；
- 确认与理由被保存。

## AT-07 低样本行为观察不会固化交易风格

**Test Objective:** 验证样本不足时不贴稳定标签。

**Starting Conditions:** 只有少量完整闭环交易，并存在疑似追价行为。

**User Role:** 主动交易者。

**Test Steps:**

1. 运行行为复盘；
2. 查看追价观察；
3. 打开样本和原始交易；
4. 在新计划中查看相关提醒；
5. 选择认可或不适用。

**Expected Outcomes:**

- 状态显示“样本不足/暂定观察”；
- 包含样本数、场景、证据和置信度；
- 不显示“你是冲动型交易者”等人格判断；
- 用户反馈被保存；
- 用户反馈不会删除原始事实。

## AT-08 计划执行生成可追溯成交

**Test Objective:** 验证从计划执行后，计划与成交双向关联且计划快照保留。

**Starting Conditions:** 一个完成审查的等待计划。

**User Role:** 主动交易者。

**Test Steps:**

1. 用户确认自己已在外部券商执行；
2. 输入真实成交时间、数量和价格；
3. 保存成交；
4. 从计划打开成交；
5. 从成交返回计划与审查。

**Expected Outcomes:**

- 产品没有自动下单；
- 计划状态、成交和时间正确；
- 双向链接工作；
- 计划原始字段不被真实成交覆盖；
- 差异数据可以计算。

## AT-09 券商导入成交安全关联或标记计划外

**Test Objective:** 验证只读预览、去重和不确定关联。

**Starting Conditions:** 券商连接只读；预览含一个可明确关联、一个有多个候选计划、一个无计划成交。

**User Role:** 主动交易者。

**Test Steps:**

1. 获取只读成交预览；
2. 确认导入；
3. 查看三个成交的关联状态；
4. 为多候选成交手工选择计划；
5. 再次同步同一批成交。

**Expected Outcomes:**

- 导入前不写数据库；
- 明确关联、待确认和计划外状态正确；
- 系统不静默猜测多候选关系；
- 再次同步不重复创建；
- 断开券商不删除已导入成交。

## AT-10 复盘区分过程质量与盈亏

**Test Objective:** 验证亏损但按计划执行、盈利但计划外执行不会被错误评价。

**Starting Conditions:** 两笔闭合交易：A 亏损但按计划执行；B 盈利但追价且扩大风险。

**User Role:** 主动交易者。

**Test Steps:**

1. 打开 A 的复盘；
2. 检查研究、计划、执行和结果四部分；
3. 打开 B 的复盘；
4. 比较过程质量与盈亏；
5. 完成一分钟复盘。

**Expected Outcomes:**

- A 不因亏损自动标记低质量；
- B 不因盈利自动标记高质量；
- 计划差异有事实证据；
- 用户可以记录当时变化；
- 完成时间进入指标但文本不进入不必要埋点。

## AT-11 北极星指标可解释

**Test Objective:** 验证纪律交易闭环覆盖率分子和分母正确。

**Starting Conditions:** 包含有计划已复盘、有计划未复盘、计划外已复盘、未闭合和时间不可计算交易。

**User Role:** 产品负责人/管理员。

**Test Steps:**

1. 运行指标查询；
2. 查看覆盖率；
3. 展开分子、分母和不可计算记录；
4. 完成一笔待复盘交易；
5. 再次查询。

**Expected Outcomes:**

- 口径与 `06-metrics.md` 一致；
- 未闭合和不可计算记录不被错误计入；
- 计划外成交进入分母；
- 完成复盘后指标按预期变化；
- 每个计数可回到原始 ID。

## AT-12 响应式、可访问性和真实状态

**Test Objective:** 验证 Top 5 路径在 1440、1024、390 和 320 宽度可用。

**Starting Conditions:** 具备成功、加载、空、局部失败、过期、未知、冲突和 AI 断流数据夹具。

**User Role:** 键盘、触控和屏幕阅读器用户。

**Test Steps:**

1. 在四个宽度依次完成今日→研究→计划→审查→复盘；
2. 仅用键盘完成导航、表单和确认；
3. 启用 reduced motion；
4. 模拟局部数据失败和 AI 断流；
5. 检查控制台和水平溢出。

**Expected Outcomes:**

- 关键操作不被截断；
- 320px 无页面级水平滚动；
- 焦点、标签和错误可访问；
- reduced motion 不改变功能；
- 失败状态说明用户能否继续、重试或检查配置；
- 没有假完成、假数据或未处理控制台错误。

## Completion Evidence Matrix

每个场景至少需要：

- 对应自动化测试；
- 对应 API/数据库或 sidecar 契约证据；
- 成功与失败路径；
- 真实浏览器路径；
- 与 PRD 要求 ID 的映射。

只有文件、组件或路由存在，不足以证明场景完成。
