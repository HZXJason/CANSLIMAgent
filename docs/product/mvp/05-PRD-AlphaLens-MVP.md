# PRD：AlphaLens 交易准备与复盘 MVP

日期：2026-08-04

状态：实施基线

使用技能：Create PRD

## 1. Summary

AlphaLens MVP 将现有跨市场 CANSLIM 研究工作台升级为交易准备与行为校准工具。产品通过统一发现引擎、用户观点与计划数据链、AI 入场前风险审查、计划—执行复盘和按时段组织的“今日”入口，让用户在真实交易前想清楚、交易后看清自己。

MVP 不替用户做交易决定，不自动下单，不以短期收益或 AI 胜率证明成功。

## 3. Background

当前产品已经具备：

- 美股与 A 股股票池及 CANSLIM 筛选；
- 个股图表、基本面数据与来源状态；
- 多智能体 AI 研究与流式报告；
- 交易计划；
- 手工或券商只读导入的交易日志；
- 确定性行为复盘；
- 响应式 Web 和原生 iOS 客户端。

但现有能力仍以页面和功能为单位：筛选器、分析、计划和日志之间只有部分跳转与文本传递。系统不能完整回答一次交易为什么进入候选、用户怎样形成自己的观点、AI 审查了什么、实际执行偏离多少，以及某个行为提醒来自哪些历史样本。

同时，CANSLIM 仍是主要筛选语言，AI 分析仍容易被理解为给出最终交易方向，首页也不能承载盘前、盘中和盘后不同任务。这些问题阻碍产品形成“每天打开、每次入场前打开”的习惯。

## 4. Objective

### Objective

让首要用户能够在 AlphaLens 内完成一条可追溯的纪律交易闭环：

```text
今日准备 → 候选发现 → 研究质询 → 用户观点 → 交易计划
→ 入场前风险审查 → 用户决定 → 真实执行/放弃 → 复盘 → 行为观察
```

### Customer Outcome

用户能在入场前发现计划冲突和个人历史风险，在交易后区分研究、计划、执行和结果问题。

### Product Outcome

提高“纪律交易闭环覆盖率”，口径见 [`06-metrics.md`](06-metrics.md)。

### MVP Key Results

这些是私测验证阈值，不是收益承诺：

1. 所有通过计划执行或券商导入的成交都能被标记为“有计划”或“计划外”；
2. 有计划成交能够展示计划与执行的可观察差异；
3. 风险审查中的每条高风险提示都引用计划字段、当前证据或历史样本；
4. AI 不可用时，筛选、观点、计划、执行和人工复盘仍可使用；
5. 产品能计算纪律交易闭环覆盖率及其输入指标；
6. Top 5 主要路径在桌面与移动端均通过验收场景。

## 5. Market Segments

### 首要用户

已有真实交易、愿意使用计划，但会出现追价、提前入场、扩大止损、计划外交易或复盘中断的自主决策型主动交易者。

### 使用约束

- 不要求毫秒级行情或自动下单；
- 用户自己完成券商交易；
- MVP 私测聚焦一个主要市场和一类常用交易场景，产品保留跨市场隔离；
- 行为画像需要完整闭环样本，低样本只能生成暂定观察。

### 非目标用户

- 高频量化或自动策略执行团队；
- 只希望获得买卖信号、不愿记录计划的用户；
- 需要全市场专业终端所有实时字段的机构用户。

## 6. Value Propositions

### 从信息分散到今日聚焦

用户不用从多个工具手工拼接市场、板块和候选；系统用透明条件生成少量研究队列，并说明为什么关注、为什么可能不适合。

### 从 AI 答案到思维补全

AI 不输出替用户负责的决定，而是区分事实、推断、未知、冲突、多头、空头和证伪条件，帮助用户补全没有想到的部分。

### 从计划表单到入场前理性停顿

AI 结合技术面、新闻、情绪、市场环境和用户历史行为检查具体计划，提醒追价、风险预算冲突或过去重复模式。

### 从盈亏日志到行为校准

产品保留当时的候选、观点、计划和审查快照，将真实执行与计划对比，避免事后用结果重写原因。

## 7. Solution

### 7.1 UX and Information Architecture

MVP Web 主导航：

```text
今日 / 发现 / 研究 / 计划 / 复盘 / 设置
```

“我的”作为个人交易成长系统进入一级导航；行为观察仍与单笔复盘互相链接，避免把证据从原始复盘中割裂。

#### 主应用界面精简原则

主应用是任务型研究工作台。界面精简以缩短“看见当前任务 → 判断证据与风险 → 完成下一步”的路径为目标，不以减少业务能力或隐藏不利状态为目标。

- **任务优先**：每个页面先呈现当前任务、必要上下文和一个清晰的主要动作；同级次要动作应合并、降级或移动到对应内容附近，避免页首、导航和内容区重复表达同一入口。
- **渐进披露**：高级筛选、完整配置、长解释和低频管理动作只在用户需要时展开；默认视图保留完成当前任务所需的最小信息集，并让被收起的能力有明确、可发现的入口。
- **证据不可被“精简”掉**：来源、数据日期、样本量、置信度、未知、冲突、风险、加载、空数据、失败和断流仍是核心内容。可以压缩说明，但不能用颜色、图标或笼统结论替代可核查文字。
- **克制表达**：删除重复标题、装饰性眉标、无行动价值的口号和解释显而易见界面的文案。AI 相关文案只说明具体能力、证据来源、当前状态和用户控制，不使用拟人化、夸大或“AI 味”包装。
- **响应式重排**：桌面端允许高密度并列信息，但主要任务始终占据视觉首位；中等宽度收敛为图标导航或更少列；移动端按任务顺序改为单列，将次要信息渐进披露，而不是机械缩小桌面布局。关键操作和状态不得因断点消失，触控目标保持约 `44px`，最低支持宽度为 `320px`。

#### `/me` 个人交易成长系统的界面扩展

`/me` 属于主应用既有“证据账簿”视觉世界，不属于独立的 `frontend/design2` 概念应用。它沿用主应用的暖黑画布、米白文字、朱红焦点、宋体标题、等宽数据、栏线分区和小圆角控件，不另建个人中心式主题。

- 页面按“当前状态 → 我的交易系统 → 策略剧本库 → 行为观察 → 动态成长面板 → AI 记忆与数据”组织，以强栏线和留白分章，避免悬浮卡片堆叠。
- 过程质量与交易结果分开展示；时间范围、样本量、数据截至时间和证据数量保持可见。样本不足时只陈述事实，不推断交易风格或人格。
- 用户声明、复盘观察和 AI 建议必须标明来源与状态；AI 建议默认进入可编辑草稿，不能伪装为已采纳规则。
- AI 记忆采用逐类授权；关闭记忆不等于删除交易记录。加载、局部失败、空样本、保存中和导出失败沿用主应用的真实状态语言。
- 桌面使用高密度双栏或数据网格，窄屏回落为单列；交互控件保留可访问状态和约 `44px` 的最小触控区域。

#### 时段化今日页

- 盘前：市场状态、数据新鲜度、候选、等待计划、重要事件；
- 盘中：接近触发的计划、尚未审查计划、风险变化；
- 盘后：新成交、计划外交易、待复盘；
- 非交易日：周期复盘与下个交易日准备。

时段只改变任务排序，不隐藏其他入口。时区、休市或数据不可用时显示真实状态。

### 7.2 Top 5 Features

## F1. 可追溯决策数据链

### 目的

连接候选、研究、用户观点、计划、风险审查、执行和复盘，为后续个性化提供可靠历史。

### 核心对象

- `CandidateSnapshot`：候选入选理由、排除风险、筛选规则、来源和时间；
- `ResearchCase`：某次标的研究及分析运行引用；
- `UserThesis`：用户观点、接受/反对论点、待确认问题和证伪条件；
- `TradePlan`：触发、失效、风险和退出计划；
- `PreTradeRiskReview`：计划相关的审查快照；
- `Execution`：不可变成交事实；
- `TradeReview`：计划、执行、结果和情绪复盘；
- `BehaviorObservation`：带样本和置信度的行为证据。

### 要求

- 所有对象有稳定 ID、创建时间和更新/版本信息；
- 时间敏感数据保存快照，不用今天的数据改写过去；
- 用户可以从复盘返回原始计划和研究；
- 无法关联的成交明确标记为计划外；
- 删除或断开券商不删除已导入事实。

## F2. AI 交易计划风险审查

### 目的

在用户下单前检查计划自洽性、技术面、新闻/情绪、事件和历史行为风险。

### 输入

- 用户填写的交易计划；
- 标的和市场上下文；
- 最近研究与证据状态；
- 当前可用的价格、技术、新闻和情绪数据；
- 达到最低样本要求的行为观察。

### 输出

- `hard_conflicts`：数学、字段或事实冲突；
- `risk_warnings`：技术、波动、事件和情绪风险；
- `behavior_reminders`：历史相似行为、样本和置信度；
- `unresolved_questions`：数据不足或用户必须回答的问题；
- `changes_since_research`：自研究快照后发生的变化；
- `freshness` 与 `sources`。

### 约束

- 不输出“批准交易”“计划通过”或替用户负责的 BUY/SELL；
- 没有证据时显示无法判断；
- 用户可继续执行，但高风险提示需要确认和可选理由；
- 完整研究和快速风险审查是不同运行路径。

## F3. 计划—执行差异与复盘

### 目的

把交易结果拆成研究质量、计划质量、执行质量和结果，避免只看盈亏。

### 要求

- 成交可从计划执行生成，也可从券商只读导入后关联；
- 比较计划与真实入场价格、数量、时间和方向；
- 有可用数据时比较止损、退出和持有周期；
- 记录计划内调整、计划外偏离和当时原因；
- 过程质量和盈亏分开呈现；
- 行为观察显示样本、场景、证据和置信度；
- 少于最低完整样本时不生成稳定交易风格。

## F4. 时段化“今日”首页

### 目的

建立每天打开和每次交易前打开的任务入口。

### 要求

- 根据用户选择的市场、时区和交易日显示当前会话状态；
- 汇总候选队列、等待计划、待审查计划、计划外成交和待复盘；
- 盘前数据展示来源和新鲜度；
- 不用涨幅榜或机会通知刺激交易；
- 空状态提供下一步动作，不生成假候选；
- 首页是聚合层，不复制各模块完整功能。

## F5. 统一发现引擎

### 目的

让 CANSLIM 成为一个模板，同时为专业筛选、盘前候选和未来自然语言条件构建提供同一底层规则。

### 条件范围

- 市场和股票池；
- 基本面与 CANSLIM；
- 价格、成交量和流动性；
- 趋势、相对强度、波动和技术结构；
- 事件与数据新鲜度；
- 排除条件。

### 要求

- 筛选规则结构化、可保存、可重复运行；
- 每个候选显示命中条件、未满足条件和数据时间；
- 市场与标签继续保持非破坏性组合筛选；
- 不支持或数据不足的条件保持未知；
- 自然语言入口在结构化模型稳定后接入，只生成可见规则；
- MVP 不宣称达到专业实时日内扫描器的数据延迟。

### 7.3 AI Research Role Change

现有多智能体研究保留基本面、技术、新闻、情绪和多空辩论，但产品呈现从“AI 最终决策”改为：

- 当前证据倾向；
- 支持与反对论据；
- 事实、假设、未知和冲突；
- 证伪条件；
- 用户待确认问题。

方向与仓位保持分离。用户自己的 `UserThesis` 才能进入交易计划。

### 7.4 Technology and Contract Constraints

- Web 与 iOS 继续通过 Go `/api/v1` 和版本化 SSE 契约访问；
- Go 负责稳定 API、授权、凭据和持久化；
- Python sidecar 负责 AI 研究、计划审查和确定性行为分析；
- 交易计划和执行事实在 PostgreSQL 持久化；
- LLM Key 保持服务端加密且前端不可回读；
- 券商保持只读预览、人工确认和无下单能力；
- A 股与美股保持数据源、股票池、市场语义和涨跌色隔离；
- AI 失败不得阻断非 AI 的计划、执行和人工复盘。

### 7.5 Assumptions to Validate

1. 用户愿意在真实下单前打开 AlphaLens；
2. 用户愿意填写最少必要计划字段；
3. 具体风险审查比长报告更能改变计划；
4. 自动计划—执行差异会提高复盘完成率；
5. 用户接受带证据、可质疑的行为观察；
6. 现有或可获取数据足以支持首个盘前场景；
7. 用户愿意在券商之外维护一个决策工作台。

## 8. Release

### M0：产品与数据契约

完成本产品基线、数据对象、API/SSE 变更策略、数据库迁移方案和事件埋点定义。退出条件是 Top 5 每项都有可测试接口和验收场景。

### M1：纪律闭环基础

交付 F1、F2 和 F3 的首条端到端路径：用户观点、计划审查、执行关联和单笔复盘。退出条件是至少一笔真实形状数据能够完整往返且失败状态真实。

### M2：日常入口

交付 F4，并聚合真实候选、计划、成交和复盘待办。退出条件是盘前、盘中、盘后和休市状态均可验证。

### M3：发现引擎

交付 F5 的结构化条件与保存模板，将 CANSLIM 迁移为模板。自然语言构建器仅在规则模型和解释能力通过验收后进入。

### M4：私测与校准

使用真实交易流程验证指标和风险；修正无价值提醒、复盘摩擦和数据新鲜度问题。高级画像、更多实时字段、更多市场和更多券商属于后续版本。

## MVP Non-goals

- 自动下单、订单路由或自动调整仓位；
- AI 给出替用户负责的交易批准；
- 收益预测、胜率承诺或 AI 回测认证；
- 毫秒级行情、Level 2 盘口或完整专业终端字段；
- 社区喊单、排行榜和跟单；
- 小样本永久交易人格；
- 在 Web MVP 完成前重做原生 iOS 全部页面。

## Definition of Done

只有当 Top 5 的验收场景全部有当前状态证据、指标可计算、失败与未知状态真实、全栈测试通过且真实浏览器主要路径通过时，MVP 才能视为完成。视觉完成、单一构建成功或存在代码路径均不能单独证明完成。
