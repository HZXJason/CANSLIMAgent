# AlphaLens MVP 功能优先级

日期：2026-08-04

使用技能：Prioritize Features

## Objective

提高真实交易被提前计划、完成风险审查并在交易后得到复盘的比例，同时建立每日和入场前使用习惯。

当前没有真实用户规模、Reach 或开发工时数据，因此不伪造 ICE/RICE 精确分数。使用高/中/低定性评估，并将未知明确列出。

## Ranked Top 5

| 排名 | 能力 | 用户影响 | 实施工作量 | 价值不确定性 | 战略一致性 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 可追溯决策数据链 | 很高 | 高 | 中 | 很高 |
| 2 | AI 交易计划风险审查 | 很高 | 中高 | 高 | 很高 |
| 3 | 计划—执行差异与复盘 | 很高 | 中高 | 中 | 很高 |
| 4 | 时段化“今日”首页 | 高 | 中 | 中 | 很高 |
| 5 | 统一发现引擎 | 高 | 高 | 高 | 高 |

## 1. 可追溯决策数据链

这是其他四项的前置条件。没有候选、观点、计划、审查、执行和复盘之间的稳定关系，个性化只能猜测，指标也无法可信计算。

取舍：它本身不一定带来强烈第一眼效果，但必须先建立。实施时应交付一条可见端到端路径，避免只做数据库重构。

## 2. AI 交易计划风险审查

最直接兑现“每次交易前打开”。它必须是快速、具体、与当前计划相关的审查，而不是复用完整基本面报告。

取舍：AI 泛化、数据过期和责任边界风险高，因此必须先定义结构化输入输出和确定性检查，再接生成式解释。

## 3. 计划—执行差异与复盘

最直接兑现“交易后打开”，也是长期画像的可靠输入。优先完成单笔差异，再做跨交易画像。

取舍：券商成交不一定完整，部分成交、卖出匹配和历史缺失必须显示不可计算状态。

## 4. 时段化“今日”首页

将产品从页面集合变成日常任务入口。它只聚合真实状态，不复制功能或生成虚假机会。

取舍：首页价值依赖其他模块有真实待办，因此排在数据链、审查和复盘之后实施，设计可先行。

## 5. 统一发现引擎

让 CANSLIM 成为一个模板，并支持未来的盘前、专业筛选和自然语言条件构建。

取舍：范围最大、数据依赖最强。MVP 先完成结构化条件、保存和解释；自然语言和专业实时扫描延后到基础通过验收之后。

## Deprioritized

| 功能 | 原因 | 重新进入条件 |
| --- | --- | --- |
| 自然语言直接生成候选 | 底层条件模型尚未稳定，容易形成黑箱荐股 | F5 结构化规则与解释通过验收 |
| 稳定交易风格画像 | 完整闭环样本不足 | 至少有足够可比较样本且低置信度规则验证 |
| 完整专业日内扫描器 | 实时数据、延迟和成本未验证 | 首个市场的数据新鲜度与用户价值实验通过 |
| 更多券商与更多市场 | 扩大集成不会修复计划—执行断链 | 已有连接的关联率和去重通过验收 |
| 自动下单 | 与人拥有决定权冲突 | 不进入当前产品战略 |
| 社区、跟单、收益排行 | 刺激交易并引入错误激励 | 不进入当前产品战略 |

## Sequencing Dependencies

```text
数据对象与指标契约
  ├─ 用户观点 → 计划 → 风险审查
  ├─ 计划 → 执行 → 单笔复盘 → 行为观察
  ├─ 真实待办 → 今日首页
  └─ 条件模型 → CANSLIM 模板 → 盘前/自然语言入口
```

## Stop Conditions

- 如果用户不愿在下单前填写最少字段，应先重新设计快速计划，不扩展 AI；
- 如果风险审查不能产生具体计划修改，应停止增加更多 Agent，回到输入与证据设计；
- 如果成交无法稳定关联计划，应停止画像开发；
- 如果盘前数据无法达到声明的新鲜度，应缩小盘前承诺，不伪装实时；
- 如果通知提高交易频率而非计划覆盖率，应关闭机会型通知。
