# Pre-Mortem：AlphaLens MVP

日期：2026-08-04

使用技能：Pre-Mortem

## Failure Scenario

假设 MVP 已发布两周，但用户没有形成每天或入场前打开的习惯。风险审查被忽略，复盘仍在券商或表格中完成，筛选器只是增加了更多字段。以下从失败结果反推原因。

## Tigers：真实风险

### T1. 产品成为五个普通工具的集合

- 紧迫度：Launch-Blocking；
- 失败方式：今日、筛选、研究、计划和复盘都存在，但数据不连续；
- 缓解：M0 先交付 ID、快照和双向导航；每个阶段都用同一条真实形状交易验收；
- Owner：产品 + 全栈工程；
- Due：M0 退出门槛。

### T2. 风险审查退化为泛化说教

- 紧迫度：Launch-Blocking；
- 失败方式：提示总是“注意风险、设置止损、不要冲动”；
- 缓解：高风险提示必须引用计划字段、当前证据或历史样本；无证据时输出无法判断；
- Owner：AI 产品 + sidecar 工程；
- Due：M1 退出门槛。

### T3. AI 被理解为交易批准者

- 紧迫度：Launch-Blocking；
- 失败方式：BUY/SELL、通过/拒绝等语义压过用户观点；
- 缓解：输出契约只包含冲突、风险、行为提醒、未知和变化；从界面中弱化 AI 最终决定；
- Owner：产品 + 前端 + AI；
- Due：M1 退出门槛。

### T4. 盘前数据不够及时或语义错误

- 紧迫度：Launch-Blocking for F4/F5；
- 失败方式：昨日数据被当成盘前状态，美股/A 股时区或涨跌语义混用；
- 缓解：定义每类数据新鲜度、市场时区和降级状态；达不到标准时缩小产品承诺；
- Owner：数据 + 后端；
- Due：M3 退出门槛。

### T5. 用户嫌计划流程太慢，直接绕过产品

- 紧迫度：Fast-Follow；
- 失败方式：行情变化时，用户不愿填写完整表单；
- 缓解：最小必填字段、计划模板、自动预填、快速审查与完整审查；监控填写耗时和计划外交易；
- Owner：产品设计 + 前端；
- Due：M1 私测首轮结束。

### T6. 计划与成交错误关联

- 紧迫度：Launch-Blocking；
- 失败方式：同标的多计划、部分成交或券商重复同步导致错误复盘；
- 缓解：显式计划 ID 优先；自动关联只能提出候选并保留确认；订单 ID 去重；不确定时标记未关联；
- Owner：后端 + 数据；
- Due：M2 退出门槛。

### T7. 行为画像用小样本给用户贴标签

- 紧迫度：Launch-Blocking for behavior observations；
- 失败方式：少量盈利/亏损被解释为稳定性格；
- 缓解：只使用完整闭环；显示样本、场景、证据、置信度；允许反驳；低样本只显示观察；
- Owner：产品 + sidecar；
- Due：M2 退出门槛。

### T8. 复盘被结果污染

- 紧迫度：Launch-Blocking；
- 失败方式：系统用当前数据和最终盈亏重写当时逻辑；
- 缓解：候选、研究、观点、计划和审查保存时间快照；过程质量与结果分离；
- Owner：产品 + 后端；
- Due：M0/M2 退出门槛。

### T9. 现有 UI 重设计被误认为业务功能已完成

- 紧迫度：Launch-Blocking for completion claims；
- 失败方式：页面视觉已经呈现“计划差异/证据账簿”，但后端和真实数据链不存在；
- 缓解：验收只相信当前 API、数据库、测试和真实运行证据；静态概念动作不得进入完成清单；
- Owner：交付负责人；
- Due：每个阶段完成审计。

## Paper Tigers：被高估的担忧

### P1. 必须先拥有所有专业筛选字段

首版只需覆盖首个交易场景，并保证条件透明、可保存和可解释。字段广度不能替代候选质量。

### P2. 必须使用机器学习生成用户画像

确定性规则、统计样本和可核查证据更适合早期产品。黑箱模型不会自动提升可信度。

### P3. 没有自动下单就不算闭环

AlphaLens 的闭环是决策纪律闭环。只读成交导入和人工决定与产品定位一致。

### P4. 必须先重做 iOS 才能验证入场前使用

Web 可先验证价值和数据契约；iOS 是后续降低摩擦的重要客户端，但不应在业务模型未验证前复制不稳定范围。

## Elephants：未充分讨论的风险

### E1. 用户是否愿意离开券商工作流

调查入场前切换工具的真实阻力；验证深链、移动快速审查或浏览器固定页是否足够。

### E2. 法律与责任边界

候选排序、自然语言引导和风险审查可能被用户感知为投资建议。需要审查产品文案、输出结构、免责声明和地区要求。

### E3. 交易历史隐私

需要明确哪些数据本地保存、哪些发送给外部 LLM、如何脱敏、删除和导出，以及行为画像是否可单独关闭。

### E4. 通知可能刺激交易

只通知已有计划、数据风险和复盘待办；不推送“机会”和涨幅异动来提高打开率。

### E5. 数据成本与商业模式

专业盘前数据、新闻和实时行情可能与本地优先低成本模式冲突。MVP 必须记录各数据源成本和可替代性。

## Launch-Blocking Action Register

| Risk | Required mitigation | Owner | Due gate | Evidence |
| --- | --- | --- | --- | --- |
| T1 数据断链 | 端到端对象、快照和导航 | 产品/全栈 | M0 | API、DB、集成测试、浏览器路径 |
| T2 泛化提醒 | 结构化引用和无证据降级 | AI/sidecar | M1 | 契约测试、真实计划样本 |
| T3 AI 决策越界 | 移除批准语义，用户观点独立 | 产品/前端 | M1 | UI 文案、SSE/API 契约 |
| T4 数据时效 | 新鲜度、时区、降级规则 | 数据/后端 | M3 | 时钟边界测试、真实响应 |
| T6 错误关联 | 显式关联、候选确认、去重 | 后端 | M2 | 部分成交与重复导入测试 |
| T7 小样本标签 | 样本、场景、置信度、反馈 | 产品/sidecar | M2 | 低样本测试与 UI 状态 |
| T8 结果污染 | 不可变快照和过程/结果分离 | 后端/产品 | M0/M2 | 历史快照回放测试 |
| T9 假完成 | PRD 逐项完成审计 | 交付负责人 | 每阶段 | 当前测试和真实运行证据 |

## Review Cadence

每个里程碑结束时重新运行本预演。私测前必须逐项关闭 Launch-Blocking Tiger，不能以“已有界面”“已有类型”或单一测试通过代替端到端证据。
