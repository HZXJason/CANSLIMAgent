# AlphaLens MVP Outcome Roadmap

日期：2026-08-04

使用技能：Outcome Roadmap

## Strategic Context

路线图围绕“纪律交易闭环覆盖率”组织。每个阶段描述用户行为或产品能力的变化，不承诺固定日期；具体实现可以调整，只要阶段结果和验收标准不变。

## M0：让每次决策拥有可追溯身份

### Outcome

让候选、研究、用户观点、计划、风险审查、执行和复盘能够稳定关联，从而可以重建用户当时知道什么、计划什么和实际做了什么。

### Candidate Outputs

- 数据对象与数据库迁移；
- API 和类型契约；
- 版本化快照；
- 指标事件与可解释查询；
- 计划外交易状态。

### Exit Metrics

- 一条端到端数据链可由 ID 双向导航；
- 计划外成交不会丢失或误关联；
- 时间快照不会被当前数据覆盖；
- 纪律闭环指标能列出原始分子与分母。

## M1：让用户在入场前发现具体风险

### Outcome

让首要用户在真实交易前完成一份快速、具体且保留决定权的风险审查。

### Candidate Outputs

- 用户观点和证伪条件；
- 计划最小字段与完整度；
- 确定性计划校验；
- AI 技术、新闻、情绪和行为风险审查；
- 高风险提醒确认。

### Exit Metrics

- 每条高风险提醒均有计划字段、证据或历史样本；
- AI 不可用时确定性校验仍工作；
- 不出现“批准交易”语义；
- 审查结果可保存并在执行后复查。

## M2：让用户看见计划与执行的差异

### Outcome

让真实成交自动进入计划对比和一分钟复盘，区分过程质量与单次盈亏。

### Candidate Outputs

- 计划关联和计划外标记；
- 入场价格、数量、时间和方向差异；
- 计划内调整与计划外偏离；
- 单笔复盘；
- 带样本和置信度的行为观察。

### Exit Metrics

- 有计划成交能够计算至少一个差异；
- 不完整历史显示不可计算原因；
- 盈利不会自动标记为高质量；
- 行为观察能够返回原始样本。

## M3：让产品成为每天的任务入口

### Outcome

让用户在盘前、盘中、盘后和非交易日打开同一“今日”入口，快速看到真正需要完成的研究、审查和复盘任务。

### Candidate Outputs

- 市场会话与时区状态；
- 候选研究队列；
- 等待、接近触发和待审查计划；
- 新成交、计划外交易和待复盘；
- 数据新鲜度与失败状态。

### Exit Metrics

- 四种会话状态都有可验证排序；
- 首页只聚合真实数据；
- 用户能在两步内进入首要待办；
- 不使用机会型通知刺激交易。

## M4：让选股方式从单一 CANSLIM 变成透明发现系统

### Outcome

让用户用同一套可解释规则完成专业筛选、盘前候选和未来自然语言引导，CANSLIM 成为可修改模板。

### Candidate Outputs

- 结构化条件模型；
- CANSLIM 默认模板；
- 技术、流动性、波动和事件条件；
- 保存、运行和解释筛选器；
- 候选命中/未满足原因；
- 在基础通过验收后加入自然语言条件构建器。

### Exit Metrics

- 同一规则可重复运行；
- 用户能解释候选为何入选；
- 未知数据不会被当作失败或通过；
- 市场与标签筛选保持非破坏性；
- 自然语言不会产生不可见条件。

## M5：用真实使用校准产品

### Outcome

证明产品改变的是计划和复盘行为，而不是增加交易次数。

### Candidate Outputs

- 私测用户任务；
- 风险审查相关性反馈；
- 复盘摩擦分析；
- 行为观察接受/反驳反馈；
- 指标口径审计。

### Exit Metrics

- 北极星指标可稳定计算；
- 用户能指出至少一个由产品补全的具体风险；
- 泛化提醒得到删除或降级；
- 交易频率未被设为成功结果；
- 未验证假设被记录并进入下一轮机会树。

## Cross-phase Dependencies

- M0 是所有阶段的硬依赖；
- M1 与 M2 形成首个可独立验收的纪律闭环；
- M3 依赖真实待办，不能先用静态卡片冒充；
- M4 的自然语言入口依赖结构化筛选规则；
- 稳定交易画像依赖 M2 和 M5 的足够样本，不属于 MVP 初始承诺。
