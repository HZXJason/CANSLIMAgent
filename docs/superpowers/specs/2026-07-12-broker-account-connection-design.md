# 券商账户一键连接设计

## 目标

将设置页中需要手动填写券商 access token、私钥和本机地址的连接方式，替换为统一的账户连接体验：每家券商使用一条横向卡片，用户点击右侧按钮后完成授权或本机已登录会话检测；成功后显示已绑定账户名称。

本次覆盖长桥、老虎、富途和 IBKR，保持只读的持仓与成交同步、预览和导入语义不变。

## 券商接入策略

| 券商 | 连接方式 | 无开发者配置时的行为 |
| --- | --- | --- |
| 长桥、老虎 | 标准 OAuth 授权码回调 | 显示“需在服务端配置开发者应用”，不再要求用户粘贴令牌或密钥 |
| 富途 | 检测本机已登录 OpenD 会话 | 提示启动并登录 OpenD，然后可重新检测 |
| IBKR | 检测本机已登录 TWS 或 IB Gateway 会话 | 提示启动并登录 TWS/Gateway，然后可重新检测 |

OAuth 客户端 ID、客户端密钥和回调地址必须由服务端环境变量配置。个人账户或券商未提供 OAuth 开发者应用时，应用不会伪造网页授权流程。

## 后端边界

保留 `GET /api/v1/brokers`，并将返回内容扩展为：

- `account_name`：已验证的券商账户显示名；
- `connection_method`：`oauth` 或 `local_gateway`；
- `connection_status`：未连接、等待授权、已连接、需重连或网关不可用；
- `secure_storage_ready`：现有加密存储可用状态。

`POST /api/v1/brokers/:broker/connect` 不再接收浏览器发送的密钥。它创建一次短期连接会话，并返回动作：

- OAuth 券商返回授权 URL，浏览器跳转到券商登录页；
- 本机网关券商触发后端的 loopback 检测，返回当前检测状态与必要的启动提示。

新增 OAuth 回调路由。它验证短期、单次使用的 state 与过期时间，交换授权码，读取账户名称，随后将令牌加密保存。失败回到设置页并提供错误原因；不会创建半完成连接。

富途和 IBKR 的检测与账户读取保持后端到本机 sidecar 的边界。所有相关网络目标严格限制在 loopback；浏览器既不接触令牌，也不接触私钥和网关地址。

同步若发现授权失效或会话失效，应将连接标为“需重新连接”，并返回适合用户操作的错误信息。现有同步预览、成交确认导入和断开连接 API 继续存在。

## 数据模型

现有券商连接记录继续只持久化加密后的敏感值，新增或迁移以下非敏感元数据：

- `account_name`；
- `connection_method`；
- `connection_status`；
- `authorization_expires_at`（如券商提供）；
- OAuth 临时授权会话所需的 state、券商、创建时间、过期时间和一次性使用标记。

state 不写入日志。凭据不会通过列表或连接状态接口回显。

## 设置页

设置页固定渲染四条券商横向卡片：

- 左侧：券商名、只读能力说明和状态；
- 中间：已绑定时显示账户名称和最后同步时间；
- 右侧：根据状态显示“连接账户”“重新检测/重新连接”“同步预览”和“断开”。

OAuth 回调成功后回到设置页并刷新该卡片。卡片下方保留同步预览与成交确认导入区域。删除旧的凭据字段表单、券商选择网格和手填 Token 提示。

## 错误处理

- 缺少 OAuth 应用配置：显示明确、不可点击的配置说明；
- 用户拒绝授权、state 无效或授权码交换失败：显示错误，保留未连接状态；
- OpenD / TWS / Gateway 不可用或未登录：显示本机启动和登录说明，不创建连接；
- 同步遇到凭据失效：标为需重新连接，并保留已导入交易日志；
- 断开连接：删除加密凭据和连接元数据，不删除已导入的交易日志。

## 验证

先以测试驱动实现以下场景：

1. OAuth state 的创建、一次性消费、过期和跨券商拒绝；
2. 回调成功保存加密令牌、账户名称和已连接状态；
3. OAuth 拒绝或失败不创建连接；
4. 本机网关可用时读取账户名称，不可用时不创建连接；
5. 凭据失效会变更为需重新连接；
6. 设置页渲染四条横向卡片、各状态对应的按钮、OAuth 跳转和账户名称。

回归范围包括现有同步预览、成交确认导入、断开连接、数据库迁移，以及凭据从不回显给浏览器。

## 非目标

- 不提供自动下单或交易指令；
- 不通过浏览器自动化模拟券商登录；
- 不在没有券商开发者配置时伪造 OAuth；
- 不改变现有交易日志导入的确认步骤。
